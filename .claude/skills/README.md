# Platform Skills Directory

This directory contains **platform-level skills** that help teams onboard and customize their component analysis.

## Available Skills

### `/create-component-skill`

**Purpose**: Generate custom test failure analysis skills for your component

**What it does**:
- Fetches your component's test context from https://github.com/jctanner/odh-test-context
- Fetches architecture context from https://github.com/opendatahub-io/architecture-context
- Reads your repo's `.claude/rules/*.md` (like cypress-e2e.md)
- Combines everything into a custom `/analyze-failures` skill for your team

**Usage**:
```
/create-component-skill <github-repo-url> <framework>
```

**Example**:
```
/create-component-skill https://github.com/opendatahub-io/model-registry pytest
```

**Result**: Creates `.claude/components/model-registry/pytest/skills/analyze-failures.md`

**With additional skills**:
```
/create-component-skill <repo-url> <framework> --all-skills
```

Generates:
- `analyze-failures.md` - Main TFA skill
- `create-jira-ticket.md` - Jira integration
- `rerun-flaky-tests.md` - Automated reruns
- `notify-team.md` - Team notifications

## How It Works

### Context Sources

The skill generator combines multiple sources to create comprehensive, component-specific skills:

1. **Test Context** (https://github.com/jctanner/odh-test-context)
   - Test suite descriptions
   - Known failure patterns
   - Flaky test identification
   - Debug procedures
   - Historical context

2. **Architecture Context** (https://github.com/opendatahub-io/architecture-context)
   - Component dependencies
   - Kubernetes resources
   - Database requirements
   - API contracts
   - Related components

3. **Repository Rules** (Your repo's `.claude/rules/`)
   - Framework best practices (e.g., cypress-e2e.md)
   - Test patterns specific to your codebase
   - Team conventions
   - Common pitfalls and solutions

4. **Component Configuration** (Your `component.json`)
   - Jenkins jobs
   - Artifact patterns
   - Namespaces
   - Failure categories
   - Team information

### Example: Dashboard Component

**Input**:
```
/create-component-skill https://github.com/opendatahub-io/odh-dashboard cypress
```

**Fetches**:
1. `odh-test-context/docs/dashboard-tests.md` → Test patterns, flaky tests
2. `architecture-context/components/dashboard.md` → Architecture, dependencies
3. `odh-dashboard/.claude/rules/cypress-e2e.md` → Cypress-specific rules
4. `.claude/components/dashboard/cypress/component.json` → Configuration

**Generates**:
```markdown
# Analyze Dashboard Test Failures

## Behavior
- Fetch from Jenkins: cypress/dashboard-tests
- Parse Cypress artifacts
- Check pods in: redhat-ods-applications

## Common Failures
- API call timeouts (check backend pods)
- Screenshot mismatch (update golden images)
- Selector not found (check for UI changes)
  
## Debugging Steps
[From cypress-e2e.md rules]
- Check cy.intercept() calls
- Review network tab
- Verify test data setup

## Rerun Commands
npm run cy:run -- --spec 'path/to/test.cy.ts'
```

## For Component Teams

### Standard Onboarding Flow

1. **Onboard component** (creates component.json):
   ```bash
   python3 scripts/onboard_component.py
   ```

2. **Generate skills** (creates analyze-failures.md):
   ```bash
   /create-component-skill https://github.com/{org}/{your-repo} {framework}
   ```

3. **Use your skill**:
   ```bash
   /analyze-failures --build 123
   ```

4. **Customize** (optional):
   - Edit generated skill to add team-specific context
   - Add Jira project info
   - Update Slack channels
   - Include links to team dashboards

### Improving Your Skills

To get better generated skills, contribute to:

1. **odh-test-context** - Add `docs/{your-component}-tests.md`
   - Document common failure patterns
   - List known flaky tests
   - Provide debugging steps
   - Share historical context

2. **architecture-context** - Add `components/{your-component}.md`
   - Document architecture
   - List Kubernetes resources
   - Explain dependencies
   - Define API contracts

3. **Your repo** - Add `.claude/rules/{framework}.md`
   - Framework best practices
   - Team conventions
   - Common pitfalls
   - Debugging techniques

## Skills Location

**Platform skills** (this directory):
```
.claude/components/skills/
└── create-component-skill.md    # Skill generator
```

**Component skills** (generated):
```
.claude/components/{component}/{framework}/skills/
├── analyze-failures.md          # Generated by create-component-skill
├── create-jira-ticket.md        # Optional
├── rerun-flaky-tests.md         # Optional
└── notify-team.md               # Optional
```

## Skill Naming Convention

- Platform skills: Imperative verbs (create, generate, update)
- Component skills: Descriptive names (analyze-failures, create-jira-ticket)
- All lowercase with hyphens

## Contributing New Platform Skills

To add a new platform skill:

1. Create `{skill-name}.md` in this directory
2. Follow the [Claude Skills template](https://github.com/anthropics/skills/blob/main/skills/skill-creator/SKILL.md)
3. Document in this README
4. Test with multiple components
5. Submit PR
